정적 라이브러리
=

생성은 ar 명령어로 한다. tar이랑 비슷한 명령어이다. ar은 archiver, tar은 tape archiver의 줄임말이다. 

정적 라이브러리는 ar을 주로 사용하고, 일반적인 패키징은 tar을 주로 사용하는데, 그 이유는 아래와 같다.

> The main difference you will notice is that tar maintains directory structure, while ar just contains a flat set of files. This makes ar suitable for building sets of assembled object code in separate files, while tar is more suitable for packaging up a directory for distribution.

ar은 파일 집합만 가지는 반면 tar은 디렉토리 구조를 유지하기 때문이다.


### ar 명령어로 정적 라이브러리를 만드는 방법:

ar -rcus <라이브러리 이름> <오브젝트 파일 목록>

* r: 오브젝트 파일이 새로운 파일이면 추가, 기존에 있는 파일이면 치환
* c: 새로 생성하는 아카이브여도 오류 출력 x
* u: 오브젝트 파일의 타임스탬프를 비교하고 더 최신일경우만 치환
* s: 아카이브 인덱스를 생성 (생성 안하면 느리고 에러날수도 있음)

### 예시: 

gcc ft_putchar.c ft_swap.c ... -c   
ar -rcus libft.a ft_putchar.o ft_swap.o ...

libft.a 라는 정적 라이브러리가 생성된다.

사용할 때는   
gcc main.c libft.a   
또는   
gcc main.c -L. -l ft   
처럼 사용하면 잘 컴파일된다.

-L 옵션은 링크할 라이브러리 디렉토리를 명시해주는 옵션이고, -l은 링크할 라이브러리를 명시하는 옵션이다. 접두사 lib와 확장자 .a를 제외한 이름만 넣으면 된다.

원래는 -l옵션과 -L옵션을 사용해서 컴파일하는게 맞는 것 같다.
